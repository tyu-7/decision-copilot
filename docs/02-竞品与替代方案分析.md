# Decision Copilot：竞品与替代方案分析

## 1. 分析目的

本轮竞品研究希望回答四个问题：

1. 现有项目是否已经解决了与 Decision Copilot 相同的问题？
2. 如果产品采用“权重＋评分＋推荐”，会与哪些方案趋同？
3. 哪些交互与决策机制值得借鉴？
4. 哪些机制与用户研究不符，应当主动排除或延后？

研究范围：

- [Pairwise](https://github.com/gbrlpzz/pairwise)：面向最终用户的 AHP 两两比较网页工具；
- [LLM-Council-Decide](https://github.com/danielrosehill/LLM-Council-Decide)：使用多种决策框架并行分析、生成推荐报告的 LLM 管线；
- [mcdm](https://github.com/akestoridis/mcdm)：多准则决策算法 Python 库。

## 2. 核心结论

三个项目都在帮助用户面对多个选项，但没有一个同时覆盖：

- 面向临近毕业人群的双路径发展选择；
- 区分事实、他人经验、未来预测、个人价值和未知信息；
- 判断外部信息对当前用户是否适用；
- 在证据不足时暂停推荐，指出最值得验证的问题；
- 由用户确认事实和价值，并保留最终决定权；
- 以形成可行动依据为目标，而不是只输出最高分选项。

如果 Decision Copilot 变成“输入选项和标准—自动分配权重—AI 或算法给分—输出最优选项”，就会与现有决策工具明显趋同。更有价值的切入点是：帮助用户把分散材料转化为经过确认、能够推动下一步行动的决策依据。

## 3. 竞品分类

| 项目 | 产品类型 | 输入 | 核心机制 | 输出 | 与本项目的重合 |
|---|---|---|---|---|---|
| Pairwise | 最终用户网页工具 | 标准、两两偏好、选项评分 | 简化 AHP 与加权求和 | 权重和选项排名 | 结构化比较机制重合 |
| LLM-Council-Decide | 通用 LLM 决策模板 | 自由文本决策 Brief | 多框架分析、交叉审查、主席综合 | 推荐或补充信息建议 | LLM 决策分析定位最接近 |
| mcdm | Python 算法库 | 数值决策矩阵 | SAW、MEW、TOPSIS 等 | 数值排序 | 产品层面重合较低 |
| Decision Copilot | 垂直场景决策准备工具 | 个人叙述、已有材料和用户确认 | 材料结构化、适用性判断、底线与未知识别 | 可核对的决策依据和下一步行动 | 差异化方向 |

## 4. Pairwise 分析

### 产品机制

Pairwise 将复杂选择拆成四步：输入判断标准、逐对比较重要程度、查看标准权重、按标准评价候选项并生成排名。数据默认保存在浏览器本地，不要求注册。

### 可借鉴

- 每个页面只完成一种认知任务；
- 开始前预告需要完成的比较数量；
- 相对比较比直接填写百分比权重更容易理解；
- 自动保存、本地优先和简明进度反馈；
- 结果既能快速阅读，也能展开查看依据。

### 不直接照搬

- 标准增加后，两两比较次数会迅速上升；
- 加权模型允许指标互相补偿，但用户的底线不应被高分抵消；
- 选项评分不能解决信息是否可信、是否适用于当前用户；
- 排名容易被误解为客观答案；
- 用户研究尚未证明精确权重是自然且必要的决策方式。

## 5. LLM-Council-Decide 分析

### 产品机制

LLM-Council-Decide 先从自由文本中提取选项、期限、约束、标准和缺失信息，再选择多种决策框架并行分析，通过交叉审查和 Chairman 汇总生成推荐、信心和反转条件。

### 可借鉴

- 将自由叙述转换为结构化决策上下文；
- 把期限、可逆性、利益相关者和情绪负荷纳入判断；
- 保留不同视角之间的分歧；
- 允许“需要补充信息”成为合法结果；
- 显示哪些关键事实改变后，当前判断也会变化；
- 区分必须满足的条件和可以权衡的偏好。

### 不直接照搬

- 即使识别出信息缺口，当前流程仍会继续生成分析，没有先向用户确认；
- LLM 自动推导权重和分数，可能制造未经确认的精确感；
- 多模型和多框架会增加成本、时长与阅读负担；
- 最终由 AI 给出唯一推荐，与用户承担最终决定的边界存在冲突；
- 通用分析没有专门处理毕业求职信息的来源、时效和个人适用性。

## 6. mcdm 分析

### 产品机制

mcdm 是多准则决策算法库。调用者需要先准备完整的数值矩阵，再使用 SAW、MEW、TOPSIS 等方法生成排序。它提供确定性计算，但不负责帮助普通用户理解情境或整理材料。

### 可借鉴

- 用户确认后的规则和计算应交给确定性程序；
- 如果未来加入评分，应公开计算规则并保证结果可复现；
- 可以通过敏感性分析说明哪些权重真正影响排名。

### 暂不采用

mcdm 不解决当前研究中最主要的问题：信息来自哪里、是否适用、用户底线是什么、哪些预测仍未知，以及什么时候证据已经足够。首版接入复杂算法会增加解释成本，却不一定增加用户价值。

## 7. 差异化机会

### 不把“更多分析”当作价值

用户已经可以从搜索、社交媒体、同辈和通用 LLM 获得大量观点。Decision Copilot 应减少重复整理和默认假设，而不是再生成一份更长的意见书。

### 将证据性质和适用性设为核心

同一句“这个行业发展好”可能是事实、个体经验、未来预测或建议者的价值判断。产品需要帮助用户看清它是什么、来自哪里、是否适用于自身，而不是直接把它转化成一个分数。

### 底线优先于权重

用户研究中的地点、工作方式、时间窗口和生活边界等条件具有门槛性质。产品应先发现不可接受条件，再讨论偏好强弱。

### 允许“证据还不够”

当现有材料不足以支持取舍时，系统可以指出最值得补充的事实或一次低成本验证行动，而不是为了给答案而勉强推荐。

### 以行动准备度替代正确答案

结果不仅回答当前材料更支持哪一侧，还应说明：

- 当前倾向由什么支撑；
- 哪项未知最可能改变判断；
- 哪些代价已经被用户明确接受；
- 下一步应该查询、询问、试做、等待还是正式承诺；
- 什么信号出现时需要重新评估。
